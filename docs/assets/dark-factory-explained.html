THE DARK FACTORY

A crew of AI agents that runs the to-do list of The Warden's Oak (a text-based Discord RPG) on a schedule, while one human keeps the only key that matters.

1board (GitHub Projects) as the control panel
5scheduled loops + 1 on-call specialist
5 minheartbeat tick that wakes the factory
1rule the whole thing hangs on

01The one rule

Agents may only do work a human has explicitly approved. On the board, that means a card must sit in Approved (you moved it there, nobody else can), or carry a standing-approval label like auto:docs that limits it to a safe class of work. Everything else is read-only for the machines. This is checked twice: once in each agent's own instructions, and once by an auditor that re-checks every open pull request against the board.

Think of it as a workshop where the staff can build anything, but only from signed work orders. You are the only person who signs.

02The board is the whiteboard

A GitHub Projects board called Dark Factory is the single control plane. The agents read it and write it; you steer by moving cards. Cards flow left to right:

Inboxraw idea
→
Triagedscoped, ready
→
Approvedhuman only 🔑
→
In Progressthe ledger owns it
→
In ReviewPR open for you
→
Donemerged; the ledger closes the card
Blockedneeds a human decision; reachable from anywhere except Done

Priority labels (P0 to P3) rank cards within a column, so when a builder asks "what next?", the answer is deterministic: highest priority first, then oldest.

03The crew

Each worker is an AI agent with a written job description (in .pi/agents/) and a fixed schedule (in .pi/subagents/schedules/). None of them remember yesterday directly; they keep notes in a small memory folder instead, one dated fact per line.

Triage

the receptionist
every 12 hwrites no code

Twice a day it cleans the Inbox: merges duplicates, links design docs, drafts acceptance criteria, asks you questions in card comments, then moves cards to Triaged (or Blocked if it's stuck).

Executor

the shift starter (redefined)
once a daystarts model work

It used to build whole features in one long, fragile session. Now it's thin: once a day it runs one command that picks an approved card (or rescues a crashed one) and registers a job in the ledger. Building happens stage by stage after that.

Sweeper

the auditor and janitor
every 48 hwrites no code

Re-checks that every open PR traces back to an approved card, re-runs CI checks on idle PRs, resets stalled cards, marks merged work Done, and posts a digest.

Scrumo

the scrum master in your DMs
Tue + Thu eveningwrites no code

Reads the board, the roadmap and the changelog, then sends you a private Discord message: what changed, what's blocked, and exactly three recommended actions phrased as decisions you can just take.

Meta-oil

the one that studies the factory itself
Fri + Sat eveningwrites no code

Measures the factory's own transcripts: wasted tokens, repeated failed commands, costly model choices. Sends you up to five numbered improvement proposals; you vote with emoji reactions (1️⃣ to 5️⃣, ✅, ❌). Only an approved proposal gets applied, as a PR you review.

Escalator

the on-call specialist
on demanddeep thinking

Not scheduled. When a builder hits something genuinely hard (a schema change, a weird failure), it spawns as a one-shot child with a heavyweight reasoning model, reproduces the problem, and hands back a binding verdict.

04The heartbeat

Nobody presses a button to start these workers. A system timer (systemd) ticks every 5 minutes, and each tick walks the same short checklist:

Enough free RAM?refuse to start below ~1 GB (past OOM kills)
→
Already busy?one tick at a time, via a file lock
→
Anything due?fire the scheduled loop runs
→
Drainadvance one stage of the oldest job

A tick with nothing due exits in milliseconds and costs nothing. The clock times are phases, not appointments: a loop "anchored at 07:30" actually starts somewhere in the 07:30 to 07:35 window.

05A job: one card, six steps, a hard budget

The redefined executor turns one approved card into a job: a small JSON file on disk (.pi/factory/jobs/) that tracks exactly where the work is. Each step runs as its own short-lived process, so a crash costs one retry, not the whole job. State lives in the file, never in a process's memory. A one-command start opens the job first — branch, isolated workspace, card claimed — and the six stages below then run one process at a time.

build50 minAI: implement + commit
→
review20 minAI, read-only: fresh look
→
fix30 minAI: land the review's fixes
→
deliversecondscode: push, open PR to dev
→
reconcilesecondscode: once you merge, set Done + close the card
→
donesecondscode: clean up, archive
build 50
review 20
fix 30
Total machine budget per job: a hard cap of 100 minutes across every step and every retry. Recharging anything requires the owner's retry command.
Fail once
Quiet retry. The step goes back to ready and the next tick runs attempt 2, with whatever budget remains.
Fail twice
Card goes Blocked plus a comment and a Discord DM to you. The machines stop; you decide.
Crash mid-step
The next tick notices the dead worker, kills any leftover process, and counts it as a failed attempt. Nothing is stranded.

Rescuing crashed work (adoption): if a previous run died but left a branch with commits behind, the next start adopts it instead of building from scratch, re-entering at the review step. Committed work is never rebuilt.

Why crashes can't corrupt anything: three locks. One tick at a time (system lock), one ledger writer at a time (drain lock), and one stage at a time per job. The drain also verifies a leftover process by its kernel start time before killing it, so a recycled process ID can never trick it into killing an innocent process.

06What the machines are never allowed to do

  • Merge a PR, push to dev or main, or tag a release. Humans do all merging and releasing.
  • Execute a card that isn't Approved (or a safe auto:* class like docs-only changes).
  • Act on silence: no answer to a proposal means no, not yes.
  • Keep working after two failed attempts at the same step: it blocks and pages you instead.
